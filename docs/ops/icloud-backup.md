No Developer portal, App Store Connect or `site/` change has been made. `package.json` stays **1.0.0** because 1.0 has not yet been submitted. ## Behaviour and constraints

This is an explicit snapshot restore, not live sync. A grown-up turns on **Back up to iCloud** behind the parental gate. It is off by default. The whole section is hidden when the build flag is false, the plugin is missing or the Apple account is unavailable. Status uses only the bundle flag and `ubiquityIdentityToken`; disabled checks never obtain the key-value store. List, read, write and remove perform zero store calls before opt-in. All backup work follows app initialization and must never hold up play.

**Home pointer removed in M13 FX:** discovery lives in **Grown-ups → Progress backup**. A grown-up must opt in on this device before the restore list accesses the store. Home never probes for backups, including this device's own newly written copy. This resolves the pointer conflict in favour of A12's **zero plugin store calls before opt-in**.

`pp.backup.state` is device-local, created lazily, and holds the random progress-line ID, random installation nonce, sequence, opt-in and last successful local write. None is added to the profile. Each device writes only `pp.b.<saveId>.<deviceNonce>`; native code supplies a Keychain nonce with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, and rejects every write with a different nonce. Quick Start/Finder/iCloud device restores cannot migrate that item: a copied JS state receives a new nonce and line, clears its rescue, and disables backup before any store access. Existing installations also re-opt in once when first adopting this binding. If Keychain is unavailable, native operations refuse safely. Cloud views can be stale: a device never attempts to protect a shared key by a read/compare/write. After restore it uses the restored line and its own nonce. Reset rotates any existing local line and clears Undo even when the account, plugin or feature is unavailable; it retains all old cloud keys. The reset confirmation promises a kept backup only after listing a valid copy of this progress line. Otherwise it says “Erase all progress? This cannot be undone.” Removing a key is an explicit gated adult action.

After a save: at most one write per ten minutes. Pause/hidden and **Make a backup** flush changed snapshots; unchanged JSON is skipped. Calls are serialized, and stale snapshots from a replaced profile are dropped. Swift stores a binary property-list envelope containing zlib-compressed UTF-8 JSON, SHA-256 and metadata. Limits are six backup keys, 900 KB total including other store entries and key names, 96 KB per envelope and 256 KB raw JSON. Quota failures preserve existing copies and play; Grown-ups offers **Remove backup**. `Last backup` means local acceptance, not a guarantee that another device has received it. Propagation and deletions are eventually consistent. Account changes require a new opt-in. Native status compares a hash of the archived `ubiquityIdentityToken` against the locally approved account at launch, without obtaining the store. Gated opt-in binds that account and the Keychain nonce. Every native store operation, including write, rechecks both; account notifications revoke the binding immediately. JS also invalidates in-flight writes before queuing the local off update. Test account switches while the app is terminated as well as while it is open.

Restore and undo always pass a fresh parental gate. Restore refuses newer versions, invalid metadata/hashes and malformed saves. Decision 77 keeps this device's Pass, Starter, Road Pass entitlements, product entitlements/revocations/refund quiet time/looks-only marker, pending Piggy, pending purchase records, installation time, sessions and **this device's parent PIN**. Processed transactions are unioned. Paid looks are stripped and re-derived from this device's entitlements, including Aurora and Cosmic; the gated restore also reconciles StoreKit. Notifications and Game Center are off afterward; pending reminders are cancelled. `home.lastTick`, `vault.lastTick`, `lastCollect`, `meta.lastSeen` and `gatePausedUntil` never remain ahead of now. A restored trip’s `sentAt` is at most now and `ends` is at most now plus its advertised hours, including v7 trips.

For each locally granted transaction absent from the backup, exact gem amounts are resolved first from the durable **device-only** `pp.purchase.grants` map. Every App grant path records the product and exact amount before granting/saving/acknowledging, including Ask to Buy approvals, interrupted launch purchases, already-owned deliveries (zero gems), and current Piggy purchases. This map has no spending-history pruning; it is never uploaded. Legacy grants fall back to local purchase history or pending records; unknown legacy amounts (including old Piggy records) still refuse safely.

Imported transaction IDs are recorded in local backup state and remain in the duplicate-delivery union, but do not demand a nonexistent local gem grant on a later restore. Undo retains purchases since restore without paying imported gems twice. `pp.profile.pre-restore` retains the original JSON and line state until undo, reset or a subsequent restore. Undo is purely local and works while backup is off or the Apple account is unavailable, always behind a fresh gate. Its button appears only when a rescue parses and purchase preservation can succeed; local storage failures still return an error without discarding the rescue.

The cloud copy contains the saved profile (progress, game settings **except the parent PIN**, and saved purchase markers) and its summary. The play ledger, support diagnostics and native StoreKit journal are not copied. We operate no server that receives or can inspect the copy. Copies may be accessible to other devices sharing the same Apple account; they are not public. Switching off backup stops future cloud operations and does not delete copies. Reset/deleting the app does not remove cloud copies. A grown-up can remove individual copies in the app before switching backup off. Ordinary iPhone/computer backups remain separately controlled by their owner.

## Owner-only enabling release

1. Before enabling, review the resolved pointer behaviour above and the counsel questions in `docs/compliance.md`. Get native-speaker review of the staged copy below. Do not publish it while the flag remains false.
2. In the Apple Developer portal, select App ID **com.pocketplanet.game** and enable **iCloud → key-value storage**. Do not add CloudKit or document storage for this feature. This is an owner action; studio automation must not register the capability through automatic signing.
3. Add `com.apple.developer.ubiquity-kvstore-identifier` to `ios/App/App/App.entitlements` with the string `$(TeamIdentifierPrefix)$(CFBundleIdentifier)`. Refresh the owner's provisioning profile/signing assets. Keep `TARGETED_DEVICE_FAMILY = 1`.
4. In the same reviewed release, set `PPCloudBackup` to true. Update the dormant native-test expectations deliberately for this owner-approved enabling change; verify true flag and key-value entitlement appear together. The current committed test requires false/no entitlement.
5. Re-check App Privacy with the owner against [Apple's App Privacy details](https://developer.apple.com/app-store/app-privacy-details/). Intended label: **Data Not Collected**, because no developer/third-party collection is added by the app. This is an architecture-based assessment to verify for the enabling build, not a claim that Apple processes no data. Generate the native Privacy Report; retain the manifest SHA and dependency allowlist unless a separate reviewed change requires otherwise.
6. Publish the staged privacy, support, index and press replacements below in all six languages, plus the identical `docs/privacy.html` mirror, **in that same enabling release**. Match existing site markup and locale switches; keep the site self-hosted and script-free. Resolve operator/contact placeholders through the launch process.
7. Run `npm run typecheck`, `npm test`, formatting, the 180-day size sim, and the lead's Playwright matrix. Build/archive with Xcode, then inspect the signed entitlement (`codesign -d --entitlements :- <App.app>`) and bundle plist before distribution. Never turn the flag on without the entitlement.
8. Test on two signed devices with one Apple account: unavailable account, per-app iCloud switch off, opt-out/opt-in, pause/hidden flush, two stale views, separate device keys, reset/new line, quota/removal, newer-save refusal, purchases/refunds/Family Sharing, gate cancellation, clock jump with a v7 trip, restore and local Undo while off/signed out, delayed sync, an account switch with the app terminated, and a Quick Start device clone while both devices stay in use. Confirm zero store calls with the flag false and before opt-in. Confirm native zlib round trips at the iOS 15.4 floor. Xcode and Playwright were not run by Package D.
9. Set the release version only when preparing that release. Let `npm run ios:release` update `MARKETING_VERSION` and build numbers from a clean owner-reviewed tree. Record the archive, commit, version and flag state in `docs/qa/release.md`.

To return to dormant mode, ship false flag and remove the iCloud entitlement together; retain saved copies. Do not silently delete a family's cloud progress. Turning backup off on one device stops that device's operations, not another opted-in device's operations.
